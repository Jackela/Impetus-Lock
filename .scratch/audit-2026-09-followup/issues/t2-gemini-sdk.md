## Verified SDK facts (research, 2026-09-15 — re-verify locally after install)

- Target package: `google-genai` (PyPI latest stable 2.23.0; requires-python >=3.10; we run 3.11/3.12). Constraint to declare: `google-genai = ">=2.23,<3.0"`. After install, assert `google.genai.types.HttpRetryOptions` exists (guards the 2.x surface).
- Legacy `google-generativeai` 0.8.6: EOL since 2025-11-30 (PyPI states support "ended permanently").
- Client: `client = genai.Client(api_key=resolved_key)` — no global configure. Optional explicit retry: `genai.Client(api_key=..., http_options=types.HttpOptions(retry_options=types.HttpRetryOptions(attempts=N)))`. Client has `.close()` / context-manager support — close what you create per the provider's existing lifecycle.
- Generate: `client.models.generate_content(model=self.model, contents=full_prompt, config=types.GenerateContentConfig(temperature=..., max_output_tokens=512, response_mime_type="application/json", safety_settings=[{"category": "HARM_CATEGORY_...", "threshold": "BLOCK_MEDIUM_AND_ABOVE"}, ...]))` — safety enums as strings, same category names as the old `HarmCategory` values. Prompt construction (`_build_prompt` @209-222) stays as-is.
- Streaming: `client.models.generate_content_stream(model=..., contents=..., config=...)`, iterate `chunk.text` (no `stream=True` arg anymore) — replaces @464-471.
- Tokens: `client.models.count_tokens(model=self.model, contents=text)` → `.total_tokens` — replaces @392-393,416. Health check keeps the count_tokens approach.
- Response parsing `response.candidates[0].content.parts[i].text` shape is unchanged — keep existing parsing (@343-371).
- Errors: ONLY `google.genai.errors.APIError` (`.code`, `.message`, `.status`) with subclasses `ClientError` (4xx) / `ServerError` (5xx). **Semantic changes vs legacy:**
  1. NO `BlockedPromptException` / `StopCandidateException` anymore. Blocked prompt / stopped candidate surface as response metadata: check `response.prompt_feedback.block_reason` and candidate `finish_reason` in the response handling. The current 400 content_blocked and 502 generation_stopped paths MUST become response-field checks (exact field access defensive — verify shapes with a fake response in tests).
  2. Local client timeouts surface as httpx transport exceptions (e.g. `httpx.TimeoutException`), while server-side 504 arrives as `ServerError(code=504)` — the 504 mapping must catch both.
  3. Invalid API key is typically `ClientError(.code=400)` in the new SDK (legacy mapped `InvalidArgument`→401): dispatch on `.code` to preserve the existing 400/401/429/502/504 status semantics.
- Retry: new SDK retry defaults are version-dependent (retry_options default None → no retry in 1.62.0; newer defaults unclear) — do NOT rely on defaults. Legacy effective outbound attempts were NOT verifiable from sources (GAPIC deadline-based) — design.md requires characterizing them by measurement BEFORE choosing explicit settings.
