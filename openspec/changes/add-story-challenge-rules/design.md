# 微信故事挑战规则设计

## Context

当前 Web 的 Muse 会因停顿或主动请求触发，Loki 有随机计时和冷却。服务端生成 `provoke`、`rewrite`、`delete` 及锚点。Web 将 Muse 的 `provoke` 也用于改写最近一句，其锁过滤允许带 `aiAction` 的事务通过，接受后还会移除已从稿面消失的锁。已有任务接口能保存版本、正文和锁，干预历史还会保留用于生成的上下文。这些行为是迁移与回归检查的基线。微信挑战的插入、双向锁和不可恢复删除各有独立的业务约束。

玩法和授权边界依据[产品定义](../../../PRODUCT.md)、[首局功能设计](../../../docs/product/first-story.md)和[口述校正与挑战改写分别授权](../../../docs/adr/0001-voice-correction-and-challenge-permissions.md)。既有行为依据[智能体规范](../../specs/agentic-interventions/spec.md)、[编辑器规范](../../specs/editor-agentic-ui/spec.md)、[锁过滤](../../../client/src/components/Editor/TransactionFilter.ts)、[编辑器执行](../../../client/src/components/Editor/EditorCore.tsx)、[干预服务](../../../server/server/application/services/intervention_service.py)和[任务持久化规范](../../specs/task/spec.md)。

## Decisions

### 按局固定身份和权限

同题开局使用 `challenge_id` 解析固定的题面和初始规则版本。题面原样预填为各局正文的第一句，这一句是普通正文，作者可编辑。局内编辑只影响当下故事，题面源可继续用于好友的同题开局。初始规则包含触发条件、允许的干预动作、锁与恢复策略，以及相关能力的许可。普通模式在首锁和能力出现时就地说明。高强度或包含不可恢复删除的局开局前展示适用的锁保护、主动后果和改锁条件，或明确说明产品内删除恢复范围，并取得玩家明确确认。具体人物反应随玩家后续行动在正文中揭晓。两种模式以相同节奏推进。同题各局根据自身正文生成干预和能力组合，独立保存选择、后果、已获能力及专用改锁的使用记录。作者自行配置的规则以开局时所选版本生效，修改保存的规则可供往后的新局使用。

将微信挑战权限放在挑战应用服务。可复用模型调用、结构化响应、任务归属和乐观版本校验，实际动作权限由局内保存的规则及状态计算，不能由模型候选或客户端标记决定。既有 `POST /impetus/generate-intervention` 的 `X-Contract-Version: 2.0.0` 继续服务原 Web 调用。若复用任务存储，旧接口不得绕过挑战稿写入、原文读取或锁保护。历史 Web 草稿不自动变为挑战稿。

### 用成功入稿推动干预与奖励

普通和高强度模式的首局都从可编辑的题面首句起步。题面预填及原处编辑首句时，系统继续等待首个有效续写回合。该回合成功入稿后，系统根据新段与前文生成故事内的首锁。《来信》的首锁附在翻看信封、请女儿看笔迹或实写开场所形成一段的合法未锁边界。其他题目的锁句落点按开局规则确定。两种模式的首局顺序一致。

| 时刻         | 入稿及成长                                                                                   |
| ------------ | -------------------------------------------------------------------------------------------- |
| 开局行动     | 翻看信封、请女儿看笔迹或写下自己的第一步，新段成功入稿后出现与正文相符的首锁。               |
| 首锁后第一轮 | 烧信、留信或一段有效自由写入稿后，登记对首锁的回应并提供第一次能力选择。                     |
| 第二轮       | 买早饭或采取其他行动，可在该段中呈现上轮选中的能力，例如旧人物回场。段末可依语境出现第二锁。 |
| 第三轮       | 第二锁已入稿时，本次行动成功入稿即登记为第二锁的回应，之后才可再次选择同类能力来进化。       |

后续按开局规则允许的干预继续。标准新手局的干预为插入锁句。普通和高强度模式均保留玩家做出的烧信或留信决定。留信后仍可拆阅或核对原件，烧信后原件与未读信文均已失去。普通模式允许玩家离开这条情节。高强度模式可就同一次烧信主动呈现至多一次真正影响主角处境的后果。后果须因烧信而发生，可由旁证、他人的行动或其他已有合理来源写入正文，之后可以持续留痕。后果已经呈现时，玩家转线应继续沿该新方向，系统不可强制追问或主动再拉回同一件事。玩家主动重提时可以围绕后果继续写，保持原件烧毁的事实。以已经提交的烧信行动识别这一次后果，模型重试、恢复或重复回包不得再次呈现。

作者可以明确点选一个预设剧情行动，系统按该行动写入一段正文。作者也可以改用语音或键盘写新段，两种路径在同一局中可交替使用。正文须在当前局成功新增，含空白和标点以外的实际内容。剧情行动决定当段正文，局内能力决定以后如何出题。只浏览剧情行动或只选择能力时，回合计数保持不变。

挑战引擎以局内稳定的 `turn_id` 登记用户授权的续写。成功入稿的续写段使用 `add-wechat-voice-entry` 提供的 `segment_id` 和来源，同一 `segment_id` 对应同一个续写回合。点选剧情行动时保存作者明确选择的行动和本次 `turn_id`，让生成、失败恢复和重试沿用同一回合。提交成功时同时登记回合与入稿段的对应关系，回执未知时先核对结果或按同一标识幂等处理。模型代写须对应作者实际选择的剧情行动，自动生成候选、自动插入锁句、题面预填、编辑或恢复旧段及重试都不会登记新回合。

干预落地后，作者首个有效回合即算回应，可来自点选或自由输入。自由输入另开一条情节仍给出同等的选择机会。计数只根据用户授权、正文是否实际新增及其提交次序判断。同一个有效回合或同一次干预各最多结算一次回应。

录音、转写和入稿处理中，先完成或退出当前输入，再显示并提交仍然适用的干预或成长选择。用户开始新录音时无需等待模型。生成时记录局和正文版本。应用前若已切局或发起收笔，丢弃对应的干预响应。锚点失效时只可在该局仍满足触发条件且允许干预时重新生成。失败时保留已入稿正文，并让同一应触发轮次可安全重试。

### 能力持续影响本局的后续出题

首发有两条能力，选项写明在本局能产生什么效果。

| 能力       | 初次选中                                               | 进化后                                                                                                                                 |
| ---------- | ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| 旧人物回场 | 已登场的人物在合适的后续行动中重新出现。               | 旧人物带回线索。由系统在合适的后续行动中揭晓有独立来源的新线索，承接既有情节并提供玩家可采取的新行动。                                 |
| 换个解释   | 让后续剧情出现一种与锁句原文和已发生事实相容的新解读。 | 玩家可选定一种解释继续写，也可留下悬念。普通模式下一直保留原锁。高强度模式下，这条能力已进化且启用时，还可由玩家明确发动一次专用改锁。 |

回应只结算一次。两项都可用时供玩家选择一项。一项可用时显示该项和跳过。暂时无可用项时照常登记回应并回到写作。各情况下作者都可继续写或收笔。再次选中已取得的同类能力，在第二锁已获有效回应且还有进化空间时升级该条。两条已选能力可叠加。两条均已进化到最高等级后，之后的回应改为提供关闭或恢复一条能力的机会，也可保持当前组合。每次调整只影响之后的行动，关闭与恢复沿用已经获得的等级，并保留本局专用改锁的已用状态。

选完能力先回到剧情选项与“自己写”。选择本身不入稿，也不增加回合。下一行动可在点选成文或自由写的同轮接续中呈现已选能力，受锁的句子明确标记。如果作者自由写让呈现能力的条件失效，保留该段原文和能力，等待下一处合适情节。回场、揭晓线索和选定解释均须尊重已入稿的选择和事实。

题材和规则的发现按已完成的不同挑战顺次结算。点选、键盘和语音路径均适用。首篇至少一段有效续写并收笔时，开放《古风探案》和高强度模式。其后另一局至少一次有效回应并收笔，开放个人模式与可恢复改写。再之后另一局至少两次有效回应并收笔，开放删除规则。每一局至多满足当前一档，重试收笔按原结果恢复。打开好友卡片可按确认条件在该局使用固定版本的高级规则，永久发现仍按玩家完成的有效挑战结算。

《古风探案》的题句为“县衙还没升堂，案头已经摆好了一份结案书。”该题的场景、人物和事实由本局建立。人物回场须选本局已出场人物，解释须立足本局事实。首发两题均使用“旧人物回场”和“换个解释”。

### 锁变化由模式与玩家发动共同授权

规则配置以系统支持的条件和动作组合为限。可选触发包括作者主动索取、回应挑战后触发及按条件自动触发。插入可将新句锁定，常规改写只可面向未锁区域，新替换文字是否锁定按本局规则。删除仅移除合法的未锁目标。恢复策略约束改写、删除影响的原文。不可恢复的删除需要每局明确选择，选项说明受影响范围及可能后果。同意录音、转写或轻度校正只授权整理当次输入。普通编辑、常规 AI 干预、通用能力或恢复路径都须保留现有锁句原文和锁状态。

首发高强度模式允许使用已进化且启用的“换个解释”专用改锁。解锁和替换共用每局一次成功机会，玩家可自行择时。发动前展示目标锁句、动作、对原句或锁状态的影响，以及适用的恢复规则。服务端按局验证玩家、固定规则版本、能力等级及启用状态、显式动作、目标锁、当前稿件版本和剩余机会。解锁只改变锁状态。替换直接变更目标句并默认锁住新句。两种操作都须保留已经发生的选择及其结果。模型可在授权范围内提供替换正文，玩家确认前仅生成候选。模型输出、通用能力选择和客户端标记均不授予改锁权限。

为专用改锁请求保留稳定标识。提交时原子更新正文、锁、相关恢复状态和稿件版本，同时登记操作成功及机会已用。同一请求重试或重放已提交回执时返回该操作的原结果。并发提交时，至多一个请求能在该局成功消耗机会。玩家取消、模型失败、目标过期或版本冲突均不消耗机会，继续保留已提交的正文和锁。仍有机会时，由玩家依据最新稿件状态决定是否再发动。

常规干预提交前也要验证局、作者、版本、触发条件、动作许可、锚点和当前输入状态。可以复用安全的编辑原语。应按实际编辑器表达校验全文及多步事务中的锁内容，包括删改、撤销重做、跨锁粘贴、自动入稿、整稿替换和冲突恢复。系统读取旧数据或发现版本冲突时保留正文，并按该局规则继续保护锁。

可恢复策略让玩家在本局产品界面查看原片段，并在合法未锁位置恢复。不可恢复的删除提交以后，产品内的草稿恢复、普通撤销、干预记录的上下文、语音原文与迟到结果、导出以及分享快照均不能成为找回受影响原文的入口。落地前应核查复制链路，包括旧 Web API 可能读取的历史字段。实施可按数据边界删除相应记录或隔离用户可访问的原文路径。提示应说明在独立设备、剪贴板或已导出文件中的既存副本仍由用户掌握，产品内不可恢复并不承诺外部副本或内部技术留存的物理销毁。

### 收笔由作者决定

收笔与完成回应、选能力和发现进度各自独立。作者可从正在写作、干预待处理或待选能力等状态发起收笔。发起后暂停发出及应用干预，包括处理中返回的结果。有正在录制、点选后仍待入稿的段落或冲突时，给作者明确选择是否先处理该输入。以实际提交到本局、按局规可交付的正文固定收笔版本，交给 `add-story-sharing` 生成独立作品。作品编辑不改变挑战原稿的正文、锁或成长；作品链接只可使用作者另行明确发布的快照。

## Migration and Verification

- 新行为只用于具有明确挑战身份的新局。旧 Web 档案及现有版本接口可沿原路径读写。涉及任务和干预存储时，先用有旧数据的隔离数据库验证读写、版本冲突、回滚和归属。
- P1 先验证常规动作不能破锁，再覆盖解锁和替换成功、普通模式、能力未进化或已关闭、没有玩家发动、目标或版本过期、取消和模型失败。对同一改锁请求并发重试、成功回执丢失后重放、解锁与替换争用同一机会分别验证，检查最终正文、锁及成功次数。先看到失败，再实现最小改动，按项目规定额外复核。用确定性干预覆盖多步修改、跨客户端访问及原文恢复策略。
- 用同一来信开场重放烧信、留信、高强度后果出现后转线、玩家主动重提、能力叠加与满级调整、题材发现和好友同题新局。检查不同输入方式共享计数与结算条件。检查已保存的正文和能力可以恢复，好友新局独立建立状态。
- 真实中文上下文中的锁句质量、微信录音连续性、玩法能否促成续写，都需按批准后的验证阶段分别取证。
