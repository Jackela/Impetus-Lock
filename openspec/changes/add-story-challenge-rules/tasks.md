## 1. 明确局内合同

- [ ] 1.1 获得提案的实施批准，以设计及增量规范中的首局节奏、烧信后果、两条能力和专用改锁条件作为实现与验收依据。
- [ ] 1.2 与 `add-wechat-voice-entry` 对齐剧情点选、自由输入、入稿段到续写回合的标识关系、输入进行中及失败处理。与 `add-story-sharing` 对齐题目版本、收笔版本及发布边界。
- [ ] 1.3 核查既有 Web 干预、任务、历史和导出入口，确定版本兼容和挑战稿隔离方案，列全不可恢复删除的原文读写路径。

## 2. 实现本局干预与锁

- [ ] 2.1 先写失败用例，覆盖普通编辑、常规 AI、通用能力及直接保存绕行。检验改写、删除、插入已有锁内、粘贴、撤销、冲突恢复及多步事务。分别验证高强度模式下已进化且启用的能力可在玩家明确发动后成功解锁或替换，普通模式、能力条件不足、未经发动以及过期目标或版本均拒绝。记录用例失败原因。
- [ ] 2.2 实现独立局及固定初始规则版本，把题面预填为可编辑首句。点选、语音和键盘新段共用同一入稿和计数合同。覆盖两种模式的同一首局节奏、首锁和第二锁、重复提交、无用户选择的模型输出，以及等待干预期间切局、录音或收笔。验证留信后仍可拆阅或核对原件，烧信后失去这些行动。普通模式可转线，高强度模式就同一次烧信最多主动呈现一次有因果的切身后果。转线后沿新路线继续，主动重提可展开，原件始终保持烧毁。
- [ ] 2.3 实现开局模式说明和专用改锁发动前的目标、效果及恢复说明。验证玩家可自主择时，解锁与替换每局共用一次成功机会，替换默认锁住新句，已经发生的选择继续成立。原子提交正文、锁、恢复状态和版本，同时登记成功动作并消耗机会。验证取消、模型失败及版本冲突保留机会，同请求并发重试和成功回执重放返回原结果，解锁与替换并发只有一次成功变更。补足旧 Web 干预与任务兼容用例。涉及 P1 锁核心的改动交由未参与实现的人员复核。

## 3. 实现成长、规则配置和收笔

- [ ] 3.1 为干预后的有效续写结算一次回应，覆盖剧情点选、绕开锁句情节的自由写和重复提交。验证两项可用时能选一项，一项可用时能选或跳过，暂时没有可用项时登记回应后仍可续写。验证只点选和自由写都可随时收笔，第一篇有实际续写并收笔即开放新题材及相应叙事能力，后续逐步发现改写和删除。
- [ ] 3.2 实现“旧人物回场”和“换个解释”两条能力，并验证选能力只改变后续出题，下一行动才呈现效果并标记锁句。自由写让当轮条件失效时保留新段及能力。第二锁获得有效回应后才可再次选择同类能力予以进化，两条能力可叠加。验证“旧人物带回线索”由系统在适合的情节中揭晓独立线索并提供新行动，“换个解释”进化后普通模式可选定解释或保持留白且保留原锁，高强度模式另可使用专用改锁。两条能力均到最高等级后，验证作者可在后续回应时关闭或恢复一条，也可保持当前组合。调整在后续行动生效，已用的改锁机会不会恢复。
- [ ] 3.3 实现已发现目录内的触发和动作配置、锁与恢复设置、命名保存及复用。覆盖独立开局、回访后复用和更改设置不改已开局的规则。
- [ ] 3.4 实现改写和删除的原文恢复选项、不可恢复删除开局确认及删除目标未锁校验。验证旧正文、干预上下文、缓存、语音候选、产品内导出和分享均遵守该局的恢复条件。
- [ ] 3.5 实现随时发起收笔，从发起起暂停发出和应用干预，处理未确认的作者输入，交付收笔版本给独立发布流程。覆盖尚未发出的干预、在途干预、能力待选以及刷新恢复后直接收笔。
