# 微信小程序选题、剧情点选与自由写设计

## 小程序会话与私有稿件

无需分享卡片也可从微信搜索或最近使用直接打开小程序，再从首页选题。题面通过题目标识定位。好友从有效作品卡打开分享页，按分享规则进入同题局。题面定位和作品卡读取各自校验，作品卡不会额外授予挑战稿权限。独立邀请卡待决定。[作品卡与同题开局](../add-story-sharing/proposal.md)

打开后，小程序调用 `wx.login`，服务端用临时凭证向微信换取经验证的小程序身份，以应用与 `openid` 的组合映射到稳定内部主体，再签发仅面向小程序接口的业务会话。`session_key` 和应用密钥留在服务端。服务端用确认的主体校验每次私有读写。续期后只有确认仍为同一主体才恢复原稿和待处理内容。会话未确认时可显示题目并保留当前写作输入，暂停远端任务与 AI 操作。会话失败提供重试，既有主体的文字保持隔离。[微信登录凭证文档](https://developers.weixin.qq.com/miniprogram/dev/api/open-api/login/wx.login.html)

现有 `Task` 的用户外键关联 `users`，浏览器账号表要求邮箱和密码。建议新增小程序主体和专属私有入口，在小程序命名空间持久化首局稿件，复用项目已有的稿件、锁和乐观版本规则。既有 Web 认证路由与浏览器中间件继续使用 Cookie、CSRF 和预期账户校验。两端的身份和数据访问分别验证。[Web 账户入口](../../../client/src/AuthenticatedEntry.tsx) · [任务数据模型](../../../server/server/models/task.py) · [账户数据模型](../../../server/server/models/user.py)

## 剧情点选与自由写

开局题句预填为可编辑首句。首局默认提供可用于续写的剧情行动。玩家选择当前方向，例如翻看未拆信封上的邮戳，系统按选择与当前正文生成并提交新段。能力选项由局规提供，用于影响后续出题或应对干预。点选剧情行动或能力时，界面应清楚说明其结果。首局的续写、规则认可的成长和收笔可以全程点选完成；该路径无需请求麦克风权限。

剧情选项旁常驻“自己写”。打开后，同一处提供键盘和按住说话，无需进入设置。选择自由写无需先处理能力选项。剧情行动生成失败可重试、选择当下另一条可用路线或接管。如果先前提交状态未知，先以原输入标识核对结果。玩家离开某个待处理的动作或输入时，取消尚未提交的尝试，避免其迟到正文覆盖接管后写入的内容。已提交的正文按实际版本继续显示。

小程序负责显示剧情行动、捕获选择及跟踪提交结果。挑战服务验证作者选定的行动和当前局状态，应用生成结果。成功入稿后，剧情行动、语音和键盘的新段都由故事局规则判定。首锁或后续锁由挑战服务按局规标识。普通和高强度局选完能力后都回到行动入口。下一次行动适用的能力在该段呈现，需要锁定的句子在正文中标明。若玩家自由写使能力暂时无从发挥，则保留玩家原段和能力，等情境合适时再呈现。锁记录与剧情回合分别登记。选项标题、未入稿候选、重复回包和能力选择均无新段记录。能力与锁句如何生效见规则提案。[故事局规则](../add-story-challenge-rules/proposal.md)

## 语音识别与选型

| 路径                                 | 建议与取舍                                                                                                                                                                                                                                                                                                                                                                  |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 微信同声传译插件                     | 首选。官方文档提供普通话实时流式识别、结束回调与最长 60 秒录音，项目可直接消费识别文本，减少自建音频传输与存储。插件持有全局唯一的录音识别管理器，须串行使用并验证中止后的回调隔离。 [微信同声传译](https://developers.weixin.qq.com/miniprogram/dev/platform-capabilities/extended/translator.html)                                                                        |
| `RecorderManager` + 腾讯云一句话识别 | 插件无法由实际主体开通、数据处理条件无法落实或真机达不到体验要求时采用。松手后上传私有有界音频到服务端，由服务端直接提交短音频文件。该路径增加网络等待、凭据管理与临时音频清理。 [微信录音接口](https://developers.weixin.qq.com/miniprogram/dev/api/media/recorder/RecorderManager.start.html) · [腾讯云一句话识别](https://cloud.tencent.com/document/product/1093/35646) |

正式选定前，用实际申请主体核对插件／服务权限、小程序类目与上架条件、隐私授权和披露、处理位置及服务商留存条款，并在 iOS 和 Android 微信真机验证录音权限、中文转写、长按、弱网和切后台。现阶段仅查到公开接口，实际主体、权限、费用、延迟和隐私条件待查。采用流式插件时，须在启用录音前说明语音可能在长按期间送去识别，松手才触发新段提交。

## 输入过程与提交

一次录音从具备权限后的有效按下开始，界面明确显示录音状态和剩余时长，最长 60 秒。首次授权若结束在手势松开之后，需要重新按住才开始录音。正常松手按当前样式处理并自动入稿，成功路径无单段确认。到达时限时停录并提示松手。手势取消、来电中断或录音中切后台时结束录音并取消此次自动提交。已经松手的请求若在切后台时仍未完成，回前台后先确认归属和提交结果，再处理仍适用的待提交文本。

逐字采用识别返回文本。默认“保留口吻”只调整标点、分段、明显口误和无意的起音重复。轻度书面化可调整当前段的口语表达。两种整理模式均保留有意重复、叙述人称、人物、事件及其关系。整理只接收当次识别文本和所选样式，模型对含义或口误没有把握时保留原文。整理失败时展示识别原文，由玩家选用原文或重试。识别失败、结果为空或录音被取消时，提示重录或键入。[口述校正与挑战改写的决定](../../../docs/adr/0001-voice-correction-and-challenge-permissions.md)

每次剧情行动、语音或键盘新段捕获内部主体、会话代次、局、稿件和入稿目标版本。剧情行动以点选时的局内 `turn_id` 查询或重试；语音和键盘以新段标识 `segment_id` 查询或重试。提交端在同一原子操作中校验身份、局、稿件版本与锁，写入正文并登记输入来源和结果。写入结果未知时，先查提交结果或做有条件的幂等重试。若期间稿件版本改变，保留可用候选，并由作者查看当前稿后选择如何处理。主体、会话代次、局或稿件已经改变时，迟到结果不回写当前页面或缓存。全局录音回调必须可归属到发起它的输入，无法可靠区分时等待之前的录音结束或安全重建后再接收新录音。

首次成功入稿的新段将 `segment_id` 及输入来源交给故事局规则判定有效续写。已入稿的新段与规则侧登记的 `turn_id` 一一对应。查看原文、恢复原文、调换当段样式、重复回包和重试均不新增续写。恢复原文通过当前稿件的版本、锁和规则校验，涉及用户后续编辑时先预览并明确确认。规则侧可读取输入状态，待当前录音、生成或提交操作完成或退出后再应用干预。作者收笔时，若有正在生成、录音、未确认入稿或有冲突的输入，先让作者选择处理或放弃，再交接收笔。[故事局规则](../add-story-challenge-rules/proposal.md)

## 音频、识别原文与分享

原声音频仅用于当次识别。小程序、转发服务和供应方在接入前须确认临时保存的明确上限和清理行为，并验证成功、失败、取消及过期分支。应用控制的临时音频在对应流程结束时清理，并对异常遗留设自动到期清理。原声不进入稿件、作品、分享、埋点或常规日志。

识别原文作为作者可见的私有资料，关联到当前局的对应段。按永久删除规则成功删除正文时，对命中内容同时清除或屏蔽游戏内的原文恢复路径，包括语音候选、冲突恢复、历史、在途结果和导出。可独立识别范围时，仅限制命中内容。此前已复制、手抄或导出的外部副本由持有人管理。分享所用成稿和撤回由 [故事分享](../add-story-sharing/proposal.md) 定义。
