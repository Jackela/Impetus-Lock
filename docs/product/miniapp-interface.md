# 小程序首局界面

微信新玩家打开小程序即可读《来信》、改题句或挑一个行动。首屏从上到下依次显示题名、可编辑题句、两条并列的剧情行动和“自己写”。两条行动在视觉上同等重要，点击后进入同一处写作页的处理状态。可继续的旧局由同一微信身份确认后提供续写。有效作品卡先展示公开快照，再提供“玩同题”。[首局剧情示例](first-story.md)

## 页面与状态

| 页面或状态           | 显示与操作                                                                                                                                                                           |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 《来信》首次打开     | 显示“十年后，你收到一封自己寄出的信”“翻看信封”“请女儿看笔迹”和“自己写”。编辑直接作用于题句。微信身份在后台确认。                                                                     |
| 点选后的处理         | 在所选行动旁显示实际状态。可用“正在连接”提示还在确认身份，用“正在写下一段”提示已开始生成。已入稿时显示新段。断网或失败时保留题句和输入，并给出当前可用操作。提交结果未知时先查回执。 |
| 普通锁句与能力       | 首锁入稿时在句旁显示锁及短说明，例如“这句将保留。你可以接着写，也可以换个方向。” 首次出现的能力在选项旁说明下一轮怎样生效，回应后才出现能力操作。                                    |
| 高强度与不可恢复删除 | 用户主动选中这类规则或从卡片进入这类同题时，开局前显示后果、锁权限或删除恢复范围及确认操作，允许返回。                                                                               |
| 自己写               | 同一处提供输入框及“按住说”。首次真正启用语音时再说明处理并请求授权。键盘升起和字放大时保留输入与提交操作的可达性。                                                                   |
| 收笔及作品           | 提供独立的私密作品页，支持保存、复制、导出 UTF-8 TXT。主动分享时预览公开字段及 AI 标识。好友先读固定的公开快照，再决定是否“玩同题”。                                                 |

## 视觉与可访问性

- 使用中文系统字体，跟随设备放大文字。正文与题句是视觉重点，正文默认建议 18 CSS 像素、行高 1.6，题句建议 24 CSS 像素、行高 1.4。长题句、双行按钮、系统放大文字时允许换行并纵向滚动。
- 白色 `#FFFFFF` 为正文底，浅灰 `#F5F5F7` 用于背景与次级区块，深灰 `#1D1D1F` 用于正文。交互强调色统一用蓝色 `#0066CC`。按钮、锁、待入稿和错误用文字或图形补足状态信息，保证背景对比度与清晰可见的焦点。
- 所有操作至少有 44 × 44 的逻辑像素触控区，在不同尺寸和文字设置下复测。两条行动在窄屏上纵向排列。主要操作避开微信胶囊、底部安全区和键盘。说明放在对应文字或操作旁，页面优先留给故事正文。

## 依据

白灰底、深色正文、留白和单一操作蓝来自 VoltAgent 对 Apple 网站视觉规则的分析。页面使用自己的文字和功能布局。44 点触控建议、文字可放大及可读对比来自 Apple HIG。先玩、在使用时解释锁句和能力、延后权限请求，取自 Apple 的新手引导与游戏设计指南，也对应 Roblox 的情境提示建议。微信广告课堂把加载速度列为转化漏斗影响因素，本项目据此把可见题句和可点第一步放在等待身份与模型之前。依据与适用范围见[来源和更新记录](../../wiki/SOURCES.md#界面与首次体验)。
