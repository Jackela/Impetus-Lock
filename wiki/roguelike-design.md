# Rogue-like 玩法借鉴

写作游戏可从 Rogue-like 借鉴共享起点、局内能力组合和局间解锁，让写作者从同一道题出发，在一局中作出自己的选择，并在后续局中获得新的选择。

## 一手资料观察

- 《Spelunky》的 Derek Yu 介绍，Daily Challenge 每天为参与者生成相同种子的关卡。相同的是关卡生成的起点，分数取决于玩家的选择和表现。原作另有每日一次的规则，这是该游戏自己的赛制。 [Derek Yu 的公告](SOURCES.md#g1)
- 《Slay the Spire》的商店页说明玩家每次旅程会遇到不同路线、卡牌和遗物，卡牌与遗物之间可以形成协同。开发者的 1.0 更新记录提到尚未解锁的卡牌和下一解锁等级的内容，表明可选内容也可以跨局逐步开放。 [Mega Crit 的商店说明](SOURCES.md#g2) · [1.0 更新公告](SOURCES.md#g3)

## bunkiten 的交互参考

以下是另一个叙事项目的源码和设计资料。 [bunkiten 原始来源](SOURCES.md#g4)

- `OptionList.tsx` 把玩家点选的行动交给 `sendPlayerTurn`。`FreeInput.tsx` 把键盘输入和非空语音转写也交给同一函数。两类入口在代码中汇入同一回合提交路径。
- bunkiten 的每轮协议规定，收到玩家回应后生成剧情正文，再给出第一人称的行动或台词选项。自由打字和语音输入均按自由行动或台词处理。
- bunkiten 的设计决定允许按预设走向推进，也允许玩家自由输入后由系统即兴续写。它提供了默认点选和自由行动可以共存的设计参考。

## 对写作游戏的启发

| 设计问题             | 可验证的推论                                                                                                                                         |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 如何让朋友写同一道题 | 可以检查共享入口是否指向同一题面与初始规则，两位参与者是否各自起稿。写作内容、选择及模型干预可以不同。若引入固定种子，可用它复现由该种子控制的部分。 |
| 如何让一局有选择     | 能力可影响写作者在本局如何应对约束或干预。用同一道题比较两种选择，检查是否各有适用情境，能否写出不同走向。现有项目术语包括锁和 Muse/Loki 干预。      |
| 如何让下一局有新鲜感 | 跨局进展可增加下一局的可选内容。验证时关注新选择是否带来不同的写法，以及新玩家能否凭起始规则完成一局。                                               |

## Impetus Lock 的设计取舍

新玩家无卡直达《来信》，可以全程点选，由系统按选定走向写正文。点选与自由写都能成篇，并按同一套规则成长。剧情选项旁常驻“自己写”，打开后同一处提供键盘和语音。首篇有实际续写并收笔开放《古风探案》和高强度模式。个人模式、可恢复改写和删除在之后不同的局里按有效回应发现。两题共用同两条能力。[当前首局与发现设计](../docs/product/first-story.md)

“把信烧掉”的三轮推演用同一前文对照两个模式。设计采用两条可进化的局内能力，分别改变谁会再出现、锁句可以怎样解释。普通和高强度共用出锁节奏，高强度另有一次主动改锁机会，须在本局取得并进化对应能力后使用。这些取舍来自本项目的设计讨论。[首局推演](../docs/product/first-story.md) · [产品定义](../PRODUCT.md) · [路线图](../ROADMAP.md)
