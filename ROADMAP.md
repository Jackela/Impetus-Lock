# Impetus Lock 产品功能路线图

**先把一道题做成一局值得写下去的故事，再扩充成长、个人模式和好友同题。** 目标载体是面向中文用户公开发布的微信小程序。每个里程碑回答一个功能问题，并交付一个可以在实际产品中验收的场景。

2026 年 11 月 26 日，工程基线为 `6f23cdf`。目前已有 Web 编辑器、模型干预和账户草稿。以下为小程序功能设计。三项 OpenSpec 均处在提案阶段。对齐后的代表性场景见[首局功能设计](docs/product/first-story.md)，整体方向见[产品定义](PRODUCT.md)。

## 五个功能里程碑

| 里程碑                            | 需要设计到什么程度                                                                                                                                               | 交付时怎样验收                                                                                                                                                                                                                                |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **一 · 点选开局，随时接管**       | 朋友发来一道题，或作者自行选题。题句自动成为可编辑的第一句。首局免注册。默认呈现剧情选项，系统按选中的行动写正文。选项旁常驻“自己写”，同一处可用键盘或按住说话。 | 纯点选、键盘和语音各完成首轮。只改题句不触发首锁。拒绝录音后仍能完成和成长，同一次选择或提交重试只入稿一段。[语音入口提案](openspec/changes/add-wechat-voice-entry/proposal.md)                                                               |
| **二 · 一局锁句挑战**             | 以“来信”跑通普通和高强度两局。玩家行动入稿后出首锁，回应后回到行动。两局都保留行动造成的损失，高强度可主动写出一次切身后果。                                     | 从同一前文分走烧信和留信，核对哪些行动还可用。分别点选和自由写离开谜团，确认都能继续或收笔。高强度交代后果后，只有玩家重提才续写该谜团。普通编辑和常规 AI 均须遵守锁。[首局推演](docs/product/first-story.md)                                 |
| **三 · 局内能力与连续回合**       | 先做“旧人物回场”和“换个解释”两条。选完回到剧情，下次行动呈现效果并可在段末出新锁。同类进化，两条可叠加。两条满级后可停用或恢复一条。                             | 分别复现两种能力带来的新行动，在同一局检查叠加、单项可选、满级调整。普通局保留锁文。高强度局显式解锁和替换共用一次机会。检查取消、失败、刷新、同时提交及能力开关后的剩余次数。[规则任务](openspec/changes/add-story-challenge-rules/tasks.md) |
| **四 · 题材、规则发现与个人模式** | 首篇有实际续写并收笔的挑战开放新题材及相应叙事能力。后续逐步介绍改写、删除。玩家可组合、命名和复用已发现的规则。                                                 | 比较只改开头就收笔、首次新增正文就收笔、好友另开同题的作品与发现记录。好友从原规则重新获能力。保存并复用两组规则，验证权限及不可恢复删除的开局确认。[挑战规则设计](openspec/changes/add-story-challenge-rules/design.md)                      |
| **五 · 收笔、作品与好友同题**     | 收笔生成独立可编辑的私密文字作品。作者能保存、带走、主动分享选定的版本。好友读作品后可以用相同开场和初始规则单独开局。                                           | A 在作品里改掉原锁句，不影响已结束的挑战稿。B 打开 A 的卡片，看不到原声、私密稿和操作历史。B 重开同题后有独立的锁句、选择和结局。撤回卡片后再打开能得到明确反馈。[作品与分享提案](openspec/changes/add-story-sharing/proposal.md)             |

里程碑一用一道题跑通只点选的首轮，再用同一道题验证打字、口述接管和识别失败。里程碑二就要接通最简收笔，这样前两步已经能完整跑一局。里程碑五再完善作品编辑、卡片、撤回和第二位作者的入口。三、四都依赖挑战的确定性记录与局内权限，分享的对外版本还依赖可固定的初始规则。

## 设计评审和交付依据

| 检查对象     | 采用的材料或方法                                                                                                                                                                                                                                                                                 |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 产品决定     | 在[首局推演](docs/product/first-story.md)逐段看用户说什么、系统写什么、在哪个时刻出现选择。已确认行为随同对应的[术语](CONTEXT.md)和提案同步。待讨论选项不计入已实现范围。                                                                                                                        |
| 首发任务     | [输入任务](openspec/changes/add-wechat-voice-entry/tasks.md)、[玩法任务](openspec/changes/add-story-challenge-rules/tasks.md)、[作品任务](openspec/changes/add-story-sharing/tasks.md)分别列实现顺序和失败场景。三项提案在仓库内审阅。议题存在时按[项目约定](docs/agents/issue-tracker.md)关联。 |
| 保护已有写作 | 复用适用的服务端模型调用和草稿版本校验，保留 Web 账户、旧稿与旧 API 的合同。改及 P1 锁路径先写失败测试并安排独立复核。完整门禁以[工作约定](AGENTS.md)为准。                                                                                                                                      |
| 正式发布     | 实施后在 iOS、Android 微信真机验证输入、切后台、网络失败及双账号同题。查明主体、AppID、类目、正式域名、录音授权与隐私说明。走微信审核与负责人发布确认，最后用普通账号复核正式版。[微信平台依据](wiki/wechat-platform.md)                                                                         |

当前仓库不能证明主体已具备相应权限、正式环境可用或小程序已上线。工程验收后直接走公开发布流程，不设置邀请试用或人数门槛。

## 已有提案如何处理

| 既有提案                                                                                  | 与这五项功能的关系                                                                                                                         |
| ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| [真实中文写作评估](openspec/changes/2026-11-09-real-chinese-writing-eval/proposal.md)     | 现有合成故事可用于回归，已有盲评提案单独审阅。选项成文是否兑现玩家意图、口述是否走样、锁句是否贴合情节分别登记，模拟输出不能代替真实表现。 |
| [协作后端取舍](openspec/changes/2026-11-09-collaboration-scope-decision/proposal.md)      | 好友同题是两个独立的局。现有多人协作路由的保留或下线按原提案处理，部署时核对实际对外开放的入口。                                           |
| [草稿恢复界面整理](openspec/changes/2026-11-09-recovery-ui-decomposition/proposal.md)     | 继续列为 Web 重构。小程序的录音中断、切后台和收笔重试按手机上的真实流程验收。                                                              |
| [风格历史与比较](openspec/changes/2026-11-09-retire-or-wire-style-history-ui/proposal.md) | 旧面板的接入或退役另议。口述校正作用于刚说完的一段，由语音入口负责。                                                                       |
